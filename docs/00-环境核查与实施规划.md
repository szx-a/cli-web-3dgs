## 二、环境结论与必须修正的文档偏差

### 2.1 【阻断级】CUDA 11.8 在本机不可用

原文档写「CUDA Toolkit 11.8：经社区验证与 3DGS 代码兼容性最佳」。

- CUDA 11.8 发布于 2022 年，**不支持 sm_120（Blackwell）**，`nvcc -arch=sm_120` 直接报未知架构；官方 `diff-gaussian-rasterization` 在 RTX 50 上编译失败是已知问题（上游 issue [#1295](https://github.com/graphdeco-inria/gaussian-splatting/issues/1295)）。
- 驱动 573.22 也不接受 CUDA 11.x 运行时（CUDA 向前兼容只保证 ≥ 同大版本）。

**修正**：

| 项 | 原文档 | 本机应改为 |
|---|---|---|
| CUDA Toolkit | 11.8 | **12.8 / 12.9 / 13.x**（与驱动 573.22 匹配；优先 12.8 或 12.9） |
| 编译架构 | 默认 | 显式 `-gencode=arch=compute_120,code=sm_120`（可加 compute_90 兜底） |
| PyTorch | 未指定 | **cu128 及以上轮子**（torch ≥ 2.7 才含 sm_120 内核），**不得装 2.6 及更早** |
| VS 版本 | VS2022 | 本机 MSVC 14.44/14.50 均可；CUDA 12.8 官方支持 VS2022，若 VS2026 工具集报错则用 BuildTools 2022 的 vcvars64 |

### 2.2 【高风险】系统 Python 3.13.11 不适合跑 3DGS 生态

`torch` 对 3.13 支持尚可，但 3DGS 周边（nerfview、部分 rasterizer 构建脚本、SAM 官方实现、nerfstudio 系）在 3.13 上缺轮子或未适配。

**修正**：用已装的 `uv` 拉一个**独立 Python 3.11**，在本工作区建 `.venv`，与系统 Python 完全隔离（同时满足 AGENTS.md 要求）。
`uv` 缓存默认路径在 `C:\Users\admin\AppData\Local\uv\cache` 被沙箱拒绝，因此**必须把 `UV_CACHE_DIR` 指到工作区内**（`.uv-cache/`）。

### 2.3 【高风险】3DGS 训练器的选择必须改成「支持 sm_120」

原文档 5.1 推荐的 4 个项目（LiteGS / faster-gaussian-splatting / GS-Scale / EDGS）在文档中未给出可核验链接，且均为研究仓库，Windows + sm_120 + Python 3.13 三重风险叠加。

**修正为分层策略**（可回退，保证一定跑通）：

1. **主路线：`gsplat`（nerfstudio-project/gsplat）+ `splatfacto`**
   - 纯 Python 包，`pip install gsplat` 可源码编译，能按本机算力自动选 `sm_120`（社区已有针对 Turing→Blackwell 的自动检测实践）；
   - 自带 Mip-Splatting 抗锯齿、稀疏/大场景优化，显存比原生更省，最适合 8GB 卡；
   - 生态完整：`ns-export`、`ns-viewer`、PLY 导出全都有。
2. **备选 A：官方 `graphdeco-inria/gaussian-splatting`**，仅当需要严格复现论文结果时；需手工编译 `diff-gaussian-rasterization` + `simple-knn` 并强制 sm_120。
3. **备选 B：LiteGS 类提速项目**，作为后续性能优化实验，不作为首版依赖。

> 结论：**首版实现把「训练后端」做成可插拔的 `trainer` 接口**（`gsplat` / `official` / `custom`），默认 `gsplat`。这样文档里推荐的加速项目以后能直接接进来，不用重写流程。

### 2.4 【高风险】SAM 3 的获取门槛与网络

- SAM 3 权重在 Hugging Face 上为 **gated（需申请授权）**，社区有大量「access request / 复议」讨论（[讨论 441](https://huggingface.co/facebook/sam3/discussions/441)、[讨论 162](https://huggingface.co/facebook/sam3/discussions/162)），审批不是即时的。
- 本机 `huggingface.co` 直连测试失败（TLS/连接被中断），需要镜像（`hf-mirror.com`）或代理。
- SAM 3 是「概念提示」模型（文本/示例提示分割），与文档设想的「一键前景 mask」用法不同：更接近 **detect + track + merge** 三件套，推理更重，8GB 显存跑视频级分割会紧张。

**修正**：分割模块做成**后端可插拔** `SegmenterBackend`：

| 后端 | 门槛 | 用途 |
|---|---|---|
| `classical` | **零依赖**（纯 numpy/PIL） | 离线兜底；静置物体 + 相对均匀背景，实测合成数据 IoU 0.93~0.98 |
| `sam3` | HF 授权 + token，需镜像/代理 | 文本/概念提示分割（文档首选） |
| `sam2.1` | 公开权重，无授权门槛 | 点/框提示 + 视频传播 |
| `fastsam` | 公开、轻量 | 通用物体，速度可接受 |
| `rembg`(RMBG / U2Net) | 公开 | 纯人像/商品抠图，一键出 mask，最省事 |

GUI 与 CLI 都提供 **API Key / HuggingFace Token / 镜像地址** 的填写与持久化（存 `config/credentials.json`，权限收紧并默认加入 `.gitignore`）。

### 2.5 【中风险】缺失的可执行文件与安装方式

`COLMAP`、`FFmpeg` 均未安装；`winget` 在当前沙箱内不可用。

**修正**：优先 **项目内自带（vendored）**：下载免安装压缩包解压到 `tools/` 下，由流程配置直接指向可执行文件。

- COLMAP：官方 [下载页](https://colmap.github.io/install.html) 的 Windows 预编译包（CUDA 版）；若 4.x 无 Windows 预编译，则退回 3.11.x 或源码编译。
- FFmpeg：gyan.dev / BtbN 的 static 构建。
- 兜底：允许在 `config/pipeline.toml` 里填写任意自备路径（`colmap.exe` / `ffmpeg.exe`）。

### 2.6 【中风险】8GB 显存的现实边界

| 场景 | 可行分辨率/规模 | 说明 |
|---|---|---|
| 室内房间 / 小物件 | 1600–1920px，150–300 张 | 可跑 30k 迭代，密度控制正常 |
| 建筑外景 / 大场景 | 1200–1600px，分段训练 | 必须开 `--cap_max`/`--densify` 限制或分块 |
| 4K 原图直喂 | ❌ | 必 OOM，必须先降采样 |
| 清理阶段（SAM） | 每张单图推理 / 小批量 | 视频级传播需降分辨率或分段 |

结论：流程必须内置**显存守护**（按可用显存自动决定 `--resolution`、`--data_device cpu`、批大小与最大高斯数），并在 GUI 暴露为「画质/显存」三档预设。

## 三、架构设计（按你的意图落成可实现结构）

### 3.1 分层：流程核心 / CLI / Web 三者共用

```
                    ┌───────────────────────────────┐
                    │        流程核心 Pipeline       │
                    │  stages + context + artifacts  │
                    │  唯一的事实来源，不依赖 UI       │
                    └───────┬───────────────┬───────┘
                            │               │
                   ┌────────▼──────┐  ┌─────▼─────────────┐
                   │  CLI 入口      │  │  Web 入口 (FastAPI)│
                   │  gsflow ...    │  │  REST + SSE + 静态页│
                   └───────────────┘  └───────────────────┘
                            │               │
                            └────── 同一份 ──┘
                              JobRunner / 事件流 / 配置 / 凭据
```

硬性约束（架构红线）：

1. UI 层**不得**包含任何重建逻辑，只调用 `Pipeline.run()` 与订阅事件。
2. 每个阶段是独立可寻址单元：`gsflow run --stages frames,mask,colmap,train,export`，可断点续跑。
3. 阶段间只通过**磁盘产物 + 清单文件（manifest.json）**通信，不用内存对象传递；这样才能「关掉 GUI 明天接着跑」。
4. 配置单一来源：`config/pipeline.toml`（无凭据） + `config/credentials.json`（有凭据，0600/ACL 收紧）。
5. 所有外部程序（colmap/ffmpeg/sam）都走 `ExternalTool` 适配器，路径可配置、缺失时给出**可执行的修复提示**而不是堆栈。

### 3.4 阶段划分与接口

| # | 阶段 | 输入 | 输出 | 关键外部依赖 |
|---|---|---|---|---|
| 1 | `frames` | 视频 | 关键帧序列（可去模糊/去重） | ffmpeg |
| 2 | `mask` | 原始图 | mask + 清理图（黑背景 / 背景补全） | SAM3/SAM2/FastSAM/rembg |
| 3 | `colmap` | 清理图 | 相机内外参 + 稀疏点云 | colmap |
| 4 | `train` | 稀疏结果 + 清理图 | `point_cloud.ply` | gsplat / official |
| 5 | `export` | ply | `glb` / `spz` + 预览图 | 纯 Python / Node 查看器 |
| 6 | `metrics` | 渲染 vs 原图 | PSNR/SSIM/LPIPS + 报告 | torch |

阶段 2 的两个子模式（文档要求「清理背景 + 解决遮挡」）：

- `mode=black`：背景填黑 + mask 同步生成（COLMAP 对黑背景容忍度最好，最稳）。
- `mode=inpaint`：用 LaMa / SD-inpaint 补全遮挡区域，保留纹理连续性。**默认 `black`**，`inpaint` 作为可选增强。
- `masks` 同时导出，供 COLMAP 用 `--ImageReader.mask_path` 忽略动态物体；若开启「只用 mask 内特征」，可在 COLMAP 参数里带 mask。

## 四、分阶段实施计划

> 每阶段都有可验收的产出，验收不过不进入下一阶段。

### M0 环境就绪（阻断其他一切）
1. `UV_CACHE_DIR` 指到工作区，用 uv 建 `.venv`（Python 3.11）。
2. `nvidia-smi` + `ctypes` 补测内存/驱动，写入 `env-report.json`。
3. 安装 **CUDA Toolkit 12.8 或 12.9**（体积大，需你确认；也可先跳过，gsplat 用 PyTorch 自带 CUDA 运行时也能编译，只有编译期需要 nvcc）。
4. `torch --index-url .../cu128` + `torchvision` + `gsplat`，跑通 `sm_120` 空内核自检。
5. 下载并 vendored：COLMAP、FFmpeg。
6. 诊断命令 `gsflow doctor` 一键输出上表（缺失项 + 精确修复命令）。
- **验收**：`gsflow doctor` 全绿或给出明确待办；`python -c "import torch,gsplat; torch.zeros(1).cuda()"` 通过。

### M1 流程骨架 + 配置/凭据系统
- `PipelineContext`、`Stage` 基类、事件总线、manifest、断点续跑、日志分文件。
- `config/pipeline.toml` + 凭据读写（GUI/CLI 共用）。
- **验收**：`gsflow run --stages frames --dry-run` 在假数据上跑通并生成 job 目录与事件流。

### M2 图像清理阶段（AI 核心）
- 统一 `SegmenterBackend`；先落地 **rembg/FastSAM（无门槛，立刻可用）**，再落 **SAM2.1**，最后接 **SAM3（HF token + 镜像）**。
- 黑背景 / 补全两种模式、mask 形态学清理、批量并发、显存守护。
- **验收**：给 20 张样例图，产出 mask 与清理图，人工抽检 5 张边缘质量。

### M3 COLMAP 阶段
- 参数固化（`max_image_size=2048`、`max_num_features=8192`、`use_gpu`、`guided_matching`、`min_num_matches=32`、单模型）。
- Sequential / Exhaustive / VocabTree 自动选择（按文件名时间序探测）。
- mask 接入、稀疏质量体检（注册率、重投影误差）、失败自动降级重跑。
- **验收**：样例数据注册率 ≥90%，输出 `.bin` 可被训练阶段读取。

### M4 训练阶段（可插拔 trainer）
- `gsplat` 后端（默认）+ 显存守护 + 三档画质预设 + fp16/`--data_device cpu` 选项。
- `official` 后端（sm_120 编译脚本 + 已知补丁）。
- 训练曲线与中间快照，OOM 自动降分辨率重试。
- **验收**：8GB 卡上 150~200 张、1600px 跑完 30k 迭代不 OOM，PSNR 落库。

### M5 导出与查看
- `ply → glb`（含 SH→RGB 烘焙选项）、`ply → spz`（体积压缩）、自动生成 4 视角预览拼图。
- 内置 Web 查看器页（`gsflow web` 下 `/viewer`）+ 可选的 SuperSplat/Three.js 外链方案。
- **验收**：浏览器里能加载 `glb`，模型朝向/尺度正确。

### M6 Web GUI + CLI 完整入口
- FastAPI + SSE/WebSocket 进度；任务队列（单机串行 + 可取消）；阶段级重跑按钮。
- 页面：作业列表 / 新建作业向导（视频或图片、分割后端、参数预设）/ 实时日志 / 产物下载 / **设置页（API Key、HF Token、镜像、工具路径）**。
- CLI 与 GUI 完全同构：GUI 的「新建作业」= `gsflow run` 的等价参数。
- **验收**：GUI 建作业 → CLI 能看到同一 job；CLI 建作业 → GUI 能实时看进度并断点续跑。

### M7 度量 / 报告 / 踩坑归档
- PSNR/SSIM/LPIPS 报告 + `docs/03-踩坑记录.md`。
- 踩坑与架构决策同步写入记忆体 **cgcv**（一条一主题：环境陷阱、编译陷阱、网络/镜像、显存调参、COLMAP 失败模式、架构取舍）。
