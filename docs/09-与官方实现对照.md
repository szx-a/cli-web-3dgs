# 09 · 与官方 / 社区前沿实现的对照

对照对象：
- **官方 gsplat** `examples/simple_trainer.py` 的 `DefaultStrategy`（我们用的光栅化器就是它）；
- **原始 3DGS**（graphdeco-inria/gaussian-splatting）的训练超参；
- 社区前沿：**Mip-Splatting**（antialiased 光栅化）、**AbsGS**（绝对梯度致密化）、**2DGS**（法线/深度畸变正则）。

结论按"**一致 / 我们缺 / 我们不同且更好 / 我们不同但更差**"四类给出，并标出证据来源。

## 1. 与官方一致的项（不需要动）

| 项 | 官方 gsplat | 原始 3DGS | 我们 |
|---|---|---|---|
| 损失权重 | L1 1.0 + SSIM 0.2 | 0.8 L1 + 0.2 SSIM | 0.8/0.2 ✔ |
| `densify_from` / `refine_every` | 500 / 100 | 500 / 100 | 500 / 100 ✔ |
| `grow_grad2d` | 2e-4 | 2e-4 | 2e-4 ✔ |
| `grow_scale3d` | 0.01 | 0.01 | 0.01 ✔ |
| `prune_scale3d` | 0.1 | 0.1 | 0.1 ✔ |
| `prune_opa` | 0.005 | 0.005 | 0.005 ✔ |
| 位置 lr / 指数衰减 | 1.6e-4 → 1.6e-6 | 同 | 同 ✔ |

## 2. 我们**缺**的官方机制（按影响排序）

| 机制 | 官方默认 | 我们 | 影响 |
|---|---|---|---|
| **不透明度重置** | `reset_every=3000`（重置到 0.01）| `balanced`/`solid` 为 **0（关闭）**，`quality` 为 3000 | `solid` 缺了"周期性把弱高斯打回 0.01 再让它自己长回来"的筛选；实测 92% 的高斯停在 0.10–0.15（正好是不透明度下限），表面是"多层半透明"而非实心 |
| **致密化窗口** | `refine_stop_iter=15000` | DEFAULTS 4000；`solid` 预设 **10000** | 高斯数量被过早冻结（40 万），近距离放大时每个高斯覆盖像素更多 ⇒ 更软 |
| **SH 阶数递增** | `sh_degree_interval=1000`（0→3）| 固定 3 | 早期高阶 SH 更容易过拟合出视角相关伪影（我们曾观察到青/洋红斑块，靠 `sh_rest_reg` 压住）|
| **AbsGS 绝对梯度** | `absgrad=True` 可显著改善致密化 | 字段存在但默认 False | 未启用，致密化质量还有提升空间 |
| `packed=True` | 训练更快 | `packed=False` | 只影响速度（约 10-20%），不影响质量 |

## 3. 我们不同、且**证据支持更好**的项

| 我们的机制 | 作用 | 证据 |
|---|---|---|
| `lambda_grad`（细节梯度损失，`solid` 用 1.0）| 提升高频细节 | 15k 剂量实验：λ=0/0.1/0.3/1.0 → LPIPS 0.2407/0.2350/0.2248/**0.2041**；60k 上 solid-v3 LPIPS 0.2116（相比无梯度版 0.2353 降 10%）|
| `max_aspect=50` + `max_scale_ratio=0.05` | 每步钳制长细比/尺度上限，直接治"细丝/针状" | 历史事故：单高斯 `scale=[15.8, 0.0, 0.033]`、aniso 7509，占 94.8% 视觉权重 ⇒ 自由视角全是丝；现在 p90 aniso=39.5，被上限截住 |
| `lambda_depth_var`（深度方差正则）| 让表面更"实" | 15k 剂量：λ=0/0.3/1.0/3.0 → 方差 0.00371/0.00241/0.00150/0.00089 |
| `sh_rest_reg=0.003` | 抑制高阶 SH 过拟合 | 关掉时自由视角出现青/洋红/绿斑块 |
| 掩码内 PSNR/SSIM + 留出集评估 | 黑底场景下唯一有意义的指标 | 全图 PSNR 会被背景稀释（19.8 dB vs 前景 35.4 dB）|
| 贴图烘焙的遮挡测试 + gutter | 治"不同部位纹理杂糅" | 与视角一致性的中位误差 0.1448→0.0465（−68%）；梯度能量 0.0458→0.0461 |

## 4. 我们不同、但**证据支持更差**的项（应改）

| 我们的机制 | 问题 | 证据 |
|---|---|---|
| **`opacity_floor=0.10`（单边下限）** | 罚项把不透明度**钉在下限**：92% 的高斯停在 0.10–0.15，表面成了"10 层半透明"；斜视/放大时层间错位 ⇒ 发闷、拖影 | `probe_opacity_solidity.py`：p10=0.100 / p50=0.101 / p90=0.126，op>0.5 仅 3.9%；剪掉 op≤0.1 的 8% 只掉 0.09 dB ⇒ 它们几乎是"填充雾" |
| `densify_until=10000`（`solid`）/ 4000（默认）| 高斯数偏少 ⇒ 近距离软 | 3× 放大保持率：405k 高斯 **26%** vs 600k 高斯 **70%** |
| `lambda_lpips=0.10`（试过）| 反而更差 | 60k 同配置：λ=0.05 → LPIPS 0.2116；λ=0.10 → **0.2158** |

## 5. 据此的改进清单（按性价比）

1. **启用官方那不透明度重置**：`opacity_reset_interval=3000`（配合 `prune_opacity=0.05`），并把 `opacity_floor` 降到 0 或 0.02 —— 目标是让 op 分布**双峰化**（要么实心，要么被剪掉）。
2. **拉长致密化窗口**：`densify_until=12000~15000`，`cap_max=900000` —— 提高近距离清晰度（已有 600k 的数据支持）。
3. **启用 AbsGS**：`absgrad=True`。
4. **实现 SH 递增**：`sh_degree_interval=1000`（0→3），与官方对齐，减轻早期过拟合。
5. `packed=True`：纯提速。

> 注：第 1、2、3 项正在用 `img5-dense` / 后续实验验证，结论会补进本文件与 docs/03。

## 6. `official` 预设（新增，2026-10-31）

把上表的改进固化成可直接使用的预设：

| 参数 | 值 | 理由 |
|---|---|---|
| `cap_max` | **900000** | 3× 放大清晰度：405k 保持 26%、600k 保持 70% |
| `densify_until` | **14000** | 对齐官方 15000 量级 |
| `opacity_reset_interval` | **3000** | 官方默认，周期性筛掉弱高斯 |
| `opacity_floor` / `_reg` | **0.02 / 0.2** | 原 0.10/0.5 把 op 钉在下限（92% 卡在 0.10–0.15）|
| `prune_opacity` | **0.02** | 配合重置，让分布双峰化 |
| `absgrad` | **True** | AbsGS 绝对梯度致密化 |
| `sh_degree_interval` | **1000** | 官方同款 SH 递增（新实装）|
| `lambda_grad` / `lambda_lpips` | 1.0 / 0.05 | 沿用已验证的最优点 |

用法：`gsflow run --preset official ...`（验证结果回填本节）。

### 6.1 验证结果（img5，60k 步，同一 8 视角评测）

| 作业 | 配置 | 高斯数 | 尺度中位 | op 中位 | LPIPS | PSNR(m) | 1× | 2× | 3× | 3× 保持 |
|---|---|---|---|---|---|---|---|---|---|---|
| img5-solid-v3 | 旧 `solid` | 405,629 | 0.0051 | 0.101 | 0.2116 | **35.38** | 0.02082 | 0.00904 | 0.00535 | 26% |
| **img5-off** | **新 `official`** | 465,388 | 0.0043 | 0.036 | **0.2076** | 34.93 | 0.02218 | 0.01692 | **0.01314** | **59%** |
| img5-long | 100k 步 | 600,412 | 0.0042 | 0.101 | 0.2131 | **36.06** | 0.01926 | 0.01658 | 0.01352 | 70% |

**结论**
1. `official` 把 **LPIPS 从 0.2116 降到 0.2076**（−1.9%），是当前所有配置里最好的；
2. **放大 3 倍的清晰度从 0.00535 提到 0.01314（2.5 倍）**，保持率 26% → **59%** —— 正对用户"贴近看糊"的问题；
3. 代价是掩码 PSNR 低 0.45 dB（34.93 vs 35.38），比 100k 步版低 1.1 dB；
4. 视角鲁棒性良好：偏 20° 清晰度不降反升（0.01747 → 0.01948），说明不是"只在训练视角锐"。

### 6.2 一个被证伪的假设：不透明度并没有"实心化"
原以为"打开重置 + 去掉 floor"会让 op 分布双峰化。实测 `img5-off` 的
op p10/p50/p90 = **0.020/0.036/0.057**，`op>0.5` 占比 **0%** —— 反而更"淡"了。

⇒ 真正的收益来自**更多、更小的高斯**（尺度中位 0.0051 → 0.0043，数量 +15%），
而不是"把表面做实"。所以"实心度"这个目标要先放一放；
**近距离清晰度的可控变量是高斯密度与尺度，不是不透明度**。
（这条纠正了本文件第 4 节把 `opacity_floor` 当作"糊"的主因的判断：它对 op 分布的影响是真的，
但它与近距离模糊只是**相关**，不是主因。）

## 7. 算法层升级：MCMC 致密化（3DGS-MCMC, NeurIPS 2024）

社区近两年在"**致密化**"这一步上最大的算法改动，是把启发式（梯度大 → 克隆/分裂）换成
**把高斯当作从后验采样的粒子**。已实装为 `train.densify_strategy=mcmc`（走 gsplat 的 `MCMCStrategy`）。

### 数学形式
位置用 **SGLD**（随机梯度朗之万动力学）更新：

$$
x_{t+1} = x_t - \eta \nabla_x L + \sqrt{2\eta}\,\sigma_t\,\epsilon,
\qquad \epsilon \sim \mathcal{N}(0, I),\quad \sigma_t = \lambda_{\text{noise}} \cdot \eta_t
$$

其中 $\eta_t$ 是当前位置学习率（随 schedule 衰减），$\lambda_{\text{noise}}$ 是我们的
`train.mcmc_noise_lr`（默认 5e5，官方同值）。噪声项的作用是**让粒子逃出局部极小**，
从而不必靠"梯度超过 2e-4 就分裂"这种硬阈值。

配套两条离散操作（都不需要梯度阈值）：

| 操作 | 判据 | 目的 |
|---|---|---|
| **重定位** | 不透明度 < `min_opacity`（我们接 `prune_opacity`）| 把"死粒子"搬到按不透明度加权采样的存活位置，等于**重新分配预算** |
| **上限替换** | 数量达到 `cap_max` | 从加权分布里挑"最没用"的一个替换掉 |

### 与默认策略的本质差别

| | `DefaultStrategy`（官方/3DGS 原版）| `MCMCStrategy` |
|---|---|---|
| 何时加高斯 | 2D 梯度范数 > 2e-4 | 每 `refine_every` 步按**不透明度分布**采样重定位 |
| 何时删高斯 | 不透明度 < 0.005 / 尺度超限 | 只在下限以下的"死粒子"被搬走 |
| 不透明度重置 | 需要（周期 3000） | **不需要**，重定位已承担筛选 |
| 超参敏感度 | 高（grow_grad2d / prune_scale3d / reset 周期）| 低（主要就 cap_max 与 noise_lr）|

### 实装要点（踩坑）
`MCMCStrategy.step_post_backward()` 的签名是 `(params, optimizers, state, step, info, lr)`：
**必须传 `lr`**（位置学习率），且**不接受** `packed` 关键字；
而 `DefaultStrategy` 是 `(..., info, packed=False)`。所以调用处必须按策略分支，
否则 TypeError。已在训练器里按 `_is_mcmc` 分支处理。

### 验证状态
* 短跑（1500 步，cap 200k）通过：日志显示 `密度控制：MCMC 策略（3DGS-MCMC）`，
  最终 65,322 个高斯、PSNR 19.12 dB（1.5k 步的正常水平）。
* **完整 60k 步对照待跑**（off2 结束后执行），评测指标同前：LPIPS / PSNR / 1×·2×·3× 清晰度。

### 7.1 完整 60k 步对照（含 MCMC）

| 作业 | 策略 | 高斯数 | 尺度中位 | op 中位 | **LPIPS** | PSNR(m) | 1× | 3× | 3× 保持 |
|---|---|---|---|---|---|---|---|---|---|
| img5-solid-v3 | 内置（旧 `solid`）| 405,629 | 0.0051 | 0.101 | 0.2116 | **35.38** | 0.02699 | 0.00637 | 24% |
| img5-off | `official`（重置+absgrad+SH 递增）| 465,388 | 0.0043 | 0.036 | 0.2076 | 34.93 | 0.02744 | 0.00582 | 21% |
| **img5-mcmc** | **MCMC（SGLD+重定位）** | 600,000 | 0.0054 | 0.022 | **0.2053** | 32.32 | 0.02602 | 0.00591 | 23% |

**结论**
1. **LPIPS 排序：MCMC 0.2053 < official 0.2076 < solid 0.2116** —— 算法层替换确实有效（−3.0%）；
2. **PSNR 排序相反**：MCMC 32.32 dB，比 solid 低 **3.06 dB**。原因很可能是
   `noise_lr=5e5` 在 60k 步内**还没退火完**（噪声与位置学习率同比例衰减，但初始温度偏高），
   表现为画面更"松散"：感知更讨喜、逐像素更不准；
3. 近距离清晰度**三者基本持平**（保持率 21~24%）—— 见下面的更正。

### 7.2 更正：此前"official 把 3× 清晰度提升 2.5 倍"是测量偏差
`eval_jobs.py` 早期用 `xyz.min()/max()` 估场景中心。MCMC 的噪声会在远处留下少量浮点，
`min/max` 中心被拉偏 ⇒ 近距离相机指向空处（img5-mcmc 的清晰度一度全是 **0.0000**）。
改成 **1%/99% 分位数**中心后：

| 作业 | 3×/1× 保持率（旧，min/max 中心）| 保持率（新，分位数中心）|
|---|---|---|
| solid-v3 | 26% | 24% |
| official | **59%** | **21%** |
| mcmc | 0%（相机指空）| 23% |

⇒ **"official 显著提升近距离清晰度"不成立**；真实收益只有 LPIPS（0.2116 → 0.2076）。
教训：**任何"取景相关"的指标都必须用鲁棒中心**，否则模型间的差异会混进相机偏差。

### 7.3 下一步（按证据）
1. **MCMC 温度退火**：`mcmc_noise_lr` 5e5 → **1e5**，看能否在保住 LPIPS 0.205 的同时把 PSNR 拉回 35 dB；
2. 若 PSNR 恢复，则 MCMC 可作为"感知优先"预设；否则保留 `official` 作为默认、MCMC 作为实验项；
3. 三条路线的高斯数分别是 405k/465k/600k，说明 MCMC 用更多高斯换感知质量，需要配合 `cap_max` 预算。
